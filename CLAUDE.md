# Courtyard 1944 — working notes

Three.js WW2 shooter (PS1-style look), bundled with esbuild, packaged as a Windows exe with Electron.

## Commands
- `npm test` — bundle check + ESLint (`no-undef`, unused vars). Expect 0 errors, 0 warnings. Run after every edit.
- `npm run build` — bundle to `app/game.js` (what Electron and the browser load). `npm run serve` — http://localhost:8080 for `app/` (`file://` can't run the game). `npm run watch` — rebuild on save.
- `npm run exe` — exe → `outputs/Courtyard1944.exe` (Git Bash; ~2 min).
- URL flags: `?test` exposes `window.__g` (start, fire, hold, setAds, weapon, reload, hurt, state, kills, player, gun, WEAPONS, enemies, level, loadLevel, smoke, pose, lineup, rig, ai, col (collision + `S`), death (+ `poses`), nade). `?level=<id>` picks the level.
- Tracker summary for `/changes`: `node tools/tracker.mjs <out_dir>`.

## Browser smoke test (gameplay or visual changes only)
1. `npm run build`; server on 8080 (leave running; if the port is taken it already is).
2. Navigate to `http://localhost:8080/index.html?test`, take a small screenshot (`requestAnimationFrame` stalls until the pane is screenshotted).
3. `await __g.smoke()` in the browser JS tool → `{ ok, checks }` (level, fire, reload, kill, nav, death). Then read console errors.
4. For visual changes: reload, `__g.start()`, screenshot showing the change.

## Do NOT read
`app/game.js` (14 MB bundle), `src/models/*.json` (generated by `tools/bake_*.py`), `src/pack/` (user's texture pack, not in git; reference by filename), `.exe-build/`, `node_modules/`, `.check/`, `outputs/`, `archive/`, `package-lock.json`, zips/rars in `../courtyard-assets/` (read its README). Most are deny rules in `.claude/settings.json` and hidden by `.ignore`.

Large procedural asset builders — open only for texture/soldier-mesh tasks, and only the part needed: `textures.js` (pixel helpers + base `T.*`), `textures2.js` (upgrades), `textures3.js` (soldier textures), `packtex.js` (pack PNGs), `soldierGeo.js`. To add a texture: add a key in the right builder, reference it in `render/materials.js`.

## Task → files
- Weapon feel/damage/spread/reload → `core/config.js` (WEAPON_DEFS, FIRE, RELOAD); animation → `player/update.js`, `weapons/guns.js`
- Enemy stats/accuracy/shouts → `core/config.js` (ENEMY, ENEMY_FIRE); hearing/tactics/suppression/evasion/deaths → HEARING, ENEMY_TACTICS, ENEMY_SUPPRESS, ENEMY_EVADE, ENEMY_DEATH; behaviour → `enemies/tactics.js` (alerted), `enemies/ai.js` (loop, unalerted); kneel/lean/flinch/death poses → `enemies/poses.js`
- Enemy types / uniforms: `enemies/uniforms.js` (`SOLDIER_TYPES`, `LAYOUTS` in sheet pixels); spawns pick `type:` in level data; see `docs/soldiers.md`
- Enemy poses/animations → `enemies/poses.js` data (no Blender bake); how it works and the pose editor → `docs/soldiers.md`. Inspect a pose: `__g.pose(i, 'k98'|'mp40'|'nade', name, view)` then screenshot
- Enemy placement/patrols, spawn, navigation, map-specific anything → `levels/<id>/data.js`
- Level geometry → `levels/<id>/` builders (helpers in `world/geo.js`). **New level → `src/levels/README.md`.**
- HUD → `ui/hud.js`; sounds → `audio/audio.js`; shaders → `render/shaders.js`
- Player hand placement → `docs/handtune.md`; Blender re-bakes (player hands, rig) → `docs/baking.md`

## Rules
- `core/config.js` and `levels/*/data.js` are data only (no imports). Tunables go there, not in systems. Systems never hard-code a map position: put it in the level data.
- `core/state.js` imports only `config.js`. Runtime cross-module scalars go on `S`; arrays/objects in state are mutated, never reassigned.
- Keep `render/renderer.js` the first import in `game.js` (top-level side effects: level build, guns, soldier spawn).
- Units metres, +Y up, soldiers face +z, muzzle along -Z. Nearest-neighbour textures, no mipmaps (PS1 look).
- Prefer Grep + targeted Read over whole files. One change at a time; `npm test` after each.
- **Screenshot rule:** after every visual change, run the smoke test and post a screenshot showing the change, unasked. Non-visual changes: say no screenshot is needed.
- `archive/game.monolith-original.js` is the pre-refactor single file: reference only.
- Commands live in `.claude/commands/` (`/dev`, `/changes`, `/exe`).
