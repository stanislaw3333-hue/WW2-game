# Courtyard 1944 — working notes

Three.js WW2 shooter (PS1-style look), bundled with esbuild, packaged as a Windows exe with Electron.

## Commands
- `npm run check` — bundle to `.check/` (fast syntax/import check; run after every edit)
- `npm run lint` — ESLint `no-undef` + unused vars over `src/`. Expect 0 errors; the 7 warnings are known (unused vars in `textures*.js`, `catch (e)` in audio/session)
- `npm test` — check + lint
- `npm run build` — bundle to `app/game.js` (minified; the Electron shell and browser test load this)
- `npm run serve` — static server on http://localhost:8080 for `app/` (needed for browser tests; `file://` cannot run the game)
- `npm run watch` — rebuild on save
- `npm run exe` — full exe build → `outputs/Courtyard1944.exe` (Git Bash; ~2 min first run)
- Debug URL flag: `?test` — exposes `window.__g` (start, fire, hold, setAds, weapon, reload, hurt, state, kills, player, gun, WEAPONS, enemies)
- Hand tuning mode (`?test` only, `src/debug/handtune.js`; keys also in the file header and the on-screen panel): press `H` in the game. `Tab` switches left/right arm; arrows move the arm (left/right, forward/back as the player sees it), PgUp/PgDn up/down; `I`/`K` pitch, `J`/`L` yaw, `U`/`O` roll the whole arm about the grip point; Shift = fine steps; `V`/`B` next/previous camera view (first person, right, left, back, below, above); `P` prints the `HAND_OFFSETS` block to the panel and console (`P` again hides it). Edits live only in the page: the user presses `P` and pastes the block, which then goes into `HAND_OFFSETS` in `core/config.js`. Switch weapons with 1/2/3 or `__g.weapon(i)`. The mode keeps the game off the pause screen. To inspect hands yourself: `__g.start(); __g.weapon(1)` in the browser JS tool, then press `h` and `v` with the computer key action, screenshotting after each press.

## Browser smoke test (after any gameplay change)
1. `npm run build` then `npm run serve` (leave running).
2. Open `http://localhost:8080/index.html?test`, check console errors are empty.
3. Drive the game through `window.__g` with the browser JavaScript tool. A proven sequence:
   - `start()`; `weapon(1)`; `hold(true)` 800 ms; `hold(false)`; check `WEAPONS[1].ammo` dropped.
   - `reload()`; wait 2.8 s; check ammo refilled.
   - `hurt(200)`; state should become `'dead'`.
   - To test a kill: set `player.x=-40, z=6.4, yaw=Math.PI/2`, weapon(1), hold 1.6 s; `enemies[0].alive` should be false and `kills` 1.
4. Take one screenshot to confirm the scene and HUD render.
Use this instead of reading source to verify behaviour.

## Module rules
- `core/state.js` imports nothing. Keep it that way to avoid import cycles.
- Cross-module **scalars** that change at runtime go on `S` (e.g. `S.state`, `S.kills`, `S.time`). Module-local `let`s stay local.
- Arrays and objects in state (`enemies`, `player`, …) are mutated, never reassigned.
- Adding a new cross-module scalar: add it to `S` in `core/state.js`, then read/write as `S.name`.
- Import order in `game.js` matters only for top-level side effects (level build, guns build, soldier spawn). Keep `render/renderer.js` first.

## Hand placement
- Hands are baked per weapon (`tools/bake_hands.py`, `src/models/*_hands.json`); never re-bake just to move a hand: `HAND_OFFSETS` in `core/config.js` is per weapon index (0 Kar98, 1 MP40, 2 grenade), per hand `L`/`R`: `p` = grip point the hand was baked on (do not change), `d` = offset in gun space (metres; -x = player left, +z = back, +y = up), `r` = turn about `p` as [axis x, y, z, angle radians], `s` = optional uniform scale about `p` (default 1). Only hands move; weapon models and `WEAPON_DEFS` stay untouched.
- Re-bake only to change the arm or finger *shape*: add a `poseL`/`poseR` dict to that weapon's `CFG` entry in `tools/bake_hands.py` (`bend` = elbow degrees, `curl` / `thumb` = 0 open .. 1 the pack's closed grip, `roll` = forearm roll degrees; `poleL`/`poleR` give the forearm direction). Run `blender -b -P tools/bake_hands.py -- OUT.json k98|mp40|nade BoltActionRifle.fbx` (Blender 5.2 is under Program Files; the FBX is inside `../courtyard-assets/models/Player/fps-animations-sniper-rifle.zip`: unzip into a scratch folder, never into the repo), then copy OUT.json to `src/models/`. The Kar98 left arm is baked this way (bend 30, curl 0.25, thumb 0.4, roll 180); after a re-bake reset that hand's `r` in `HAND_OFFSETS` to `[0, 1, 0, 0]` and re-tune `d`.
- In the user's words "left/right/back" mean the player's first-person view: left = -x, right = +x, back = +z.

## Conventions
- Units are metres; +Y up; soldiers face +z; muzzle along -Z (three.js axes).
- Textures use nearest-neighbour filtering and no mipmaps — keep the PS1 look.
- Balance and feel numbers live in `core/config.js`. Change them there, not in the systems. Example: to make the MP40 hit harder, edit `WEAPON_DEFS[1].dmg`.
- `core/config.js` imports nothing and holds data only.
- Not yet in config (still literals in their module): fire spread, reload timings, enemy shout cooldown, and the level geometry (enemy spawns and archway waypoints ARE in config: `ENEMY_SPAWNS`, `ARCH_WAYPOINTS`).

## Task → files (open only these)
- Weapon feel/damage → `core/config.js` (WEAPON_DEFS), then `player/update.js`, `weapons/guns.js`
- Enemy count/placement/patrols → `core/config.js` (ENEMY_SPAWNS)
- Enemy behaviour → `enemies/ai.js`; enemy damage/shouts → `enemies/combat.js`; enemy look/pose → `enemies/soldiers.js`
- Level geometry → `world/yard1.js` / `yard2.js` / `detail.js` (helpers in `world/geo.js`)
- HUD → `ui/hud.js`; sounds → `audio/audio.js`; shaders → `render/shaders.js`
- Textures: `textures.js` = pixel helpers (`rng`, `tex`, `blotch`, `drawText`) + `makeTextures()` (base world `T.*`); `textures2.js` `upgradeTextures(T)` replaces some with better versions; `textures3.js` `soldierTextures(T)`. `render/materials.js` maps `T` → `M`/`SM`. To add a texture, add a key in the right builder and reference it in `materials.js`; don't read the whole file.

## Token hygiene
- `.ignore` hides `src/models/`, `archive/`, build output from Grep/Glob. Don't remove it.
- After every edit run `npm test` (check + lint) only. Run the browser smoke test only for gameplay changes.
- Browser pane gotcha: `requestAnimationFrame` stalls until the pane is screenshotted, so take a screenshot right after navigating and before driving `window.__g`.

## Workflow rules
- **Screenshot rule (mandatory):** after every visual change to the game (level, models, textures, lighting, HUD, weapons, effects), run the browser smoke test and post a screenshot that shows the change in the reply. Do this without being asked. Non-visual changes (sound, window settings, logic with no visible effect) need no screenshot, but say so.
- Make one change at a time; run `npm run check` after each.
- Commit small with a clear message once `check` passes.
- Prefer Grep + targeted Read over reading whole files.
- The `/exe` command lives in `.claude/commands/exe.md` in this folder. The repo root is this folder.
